# Synopsis

- `Twice or nothing` is an easy crypto challenge in which the players have to recover the private key of a Lamport signature scheme. The signing key is reused and there is a limit on the number of messages we can sign so one has to write a custom chosen-plaintext attack to recover the entire secret key given only 5 signatures.



# Description

- Dr. Qureshi intercepted traffic from a D9 authentication node hidden in the transit grid. The gateway predates the latest hardening directive, and the tokens it issues follow an older pattern. Secure administrative access before the patrol cycle resets.



## Skills Required

- Hash Functions

- Basic knowledge of Rust source code auditing

## Skills Learned

The first option, asks for a hex-encoded message to be signed with the `auth_key` which is generated by `issue_credentials`.

```rust
use sha2::{Sha256, Digest};
use crypto_bigint::{U256, Encoding};
use rand::{rng, prelude::*};

const N: usize = 256;

#[derive(Debug,Clone)]
struct AuthKey {
    key_pairs: [(U256, U256); N]
}
#[derive(Debug,Clone)]
struct AuthPub {
    commitments: [([u8; N/8], [u8; N/8]); N]
}

fn get_random_bytes(len: usize) -> Vec<u8> {
    let mut buf = vec![0u8; len];
    rng().fill_bytes(&mut buf);
    buf
}

fn hash_digest(s: &[u8]) -> [u8; N/8] {
    Sha256::digest(s).into()
}

fn issue_credentials() -> (AuthKey, AuthPub) {
    let key_pairs = std::array::from_fn(|_| {
        (
            U256::from_be_slice(&get_random_bytes(N/8)),
            U256::from_be_slice(&get_random_bytes(N/8))
        )
    });
    let commitments = key_pairs.iter().map(|(s0, s1)| {
                                (hash_digest(&s0.to_be_bytes()), hash_digest(&s1.to_be_bytes()))
                            })
                            .collect::<Vec<_>>()
                            .try_into()
                            .unwrap();
    (AuthKey { key_pairs }, AuthPub { commitments })
}
```

The `auth_key` looks like the signing key, i.e. the private key, and the `auth_pub` the verifying key. Based on the key generation process, one can research online this signature scheme and will figure out it is well known as the Lamport signature scheme. However, knowing the name is optional and is not required to solve the challenge.

The goal of the challenge is to provide a valid signature for the target message `d9_netadmin`.

However, looking at the code for signing, it is not directly possible to sign it, therefore we need to find an alternative way. Let us denote the Lamport keys algebraically:

The private key is a list of $N$ tuples, where the $i$-th tuple consists of two elements $(x_{i,0}\ ,\ x_{i,1})$. In other words, $SK = \{(x_{0,0}\ ,\ x_{0,1}), (x_{1,0}\ ,\ x_{1,1}), \cdots, (x_{N-1,0}\ ,\ x_{N-1,1}))\}$.

The public key, similarly, is a list of $N$ tuples where the $i$-th tuple consists of two elements $(H(x_{i,0})\ ,\ H(x_{i,1}))$, where $H$ a cryptographic hash function. In other words, $PK = \{(H(x_{0,0})\ ,\ H(x_{0,1})), (H(x_{1,0})\ ,\ H(x_{1,1})), \cdots, (H(x_{N-1,0})\ ,\ H(x_{N-1,1}))\}$.

For this challenge, the chosen hash function is SHA256 that produces 256-bit hashes.

Normally, for the signing process, the message to be signed is hashed with either $H$ or some other hash function $H'$ that produces the same digest size as $H$. Then, the $i$-th bit of the message hash is used as an index in the private key. For example, if the $i$-th bit is $0$, then $x_{i,0}$ is selected, otherwise $x_{i,1}$. More formally, the signature is a tuple of $N$ elements: $s = (x_{0,b_0}, x_{1,b_1,\ \cdots,\ x_{N-1,b_{N-1}}})$, where $b_i$ the message hash bits. The signature of the message is $s$.

For the verification process, the same message hash is computed and for each bit, say $i$, it is checked whether $H(s_i) = PK_{i,b_i}$.

# Solution

## Finding the vulnerability

It is important to note that the Lamport signature scheme is considered an ***one-time*** signature scheme which means that once the private key is used to sign a message, it should be destroyed directly and not reused for any other message and that is because the Lamport signatures leak a big part of the private key. For example, by signing a single message, exactly 50% of the private key is leaked and becomes public which is really dangerous for a cryptographic scheme. The issue is that in this challenge, the key generation process is done once so the same keys are used to sign and verify several messages. As in `Once or nothing`, the first challenge of this 2-part challenge series, this is the core vulnerability.

In contrast to `Once or nothing`, the message now is properly hashed so we cannot apply the same attack as in the first challenge. 

```rust
fn issue_token(m: &[u8], auth_key: AuthKey) -> [U256; N] {
    let message_hash = U256::from_be_bytes(hash_digest(m).into());
    let hash_bits = to_bits(message_hash);
    assert!(hash_bits.len() == auth_key.key_pairs.len(), "ERROR: The number of hash bits and the size of the secret key must match.");
    std::array::from_fn(|i| {
        let (zero, one) = auth_key.key_pairs[i];
        if hash_bits[i] { one } else { zero }
    })
}
```

Additionally, there is also a limit on the number of messages we can sign and that limit is $5$ messages.

As aforementioned, by signing a single message, we get 50% of the private key but the rest 50% is not that trivial to recover especially with $4$ messages left to sign.

# Exploitation

Let us write a python script to connect to the remote container using pwntools.

```python
host, port = sys.argv[1].split(":")
io = remote(host, port, level="error")
```

Then, we need a function that receives a message, sends it to the server to be signed and returns the corresponding signature.

```python
def get_signature(msg: str):
    io.sendlineafter(b'> ', b'1')
    # assume msg already hex
    io.sendlineafter(b": ", msg.encode())
    sig = io.recvline().strip().decode()
    if "ERROR" not in sig:
        sig = eval(sig.split(": ")[1].replace('Uint(', '').replace(')', ''))
    return sig
```

For convenience, we will use an occurencies list to keep track of which private key values are recovered. More specifically:

- If $x_{i, 0}$ is recovered, the entry for $x_i$ is increased by $1$
- If $x_{i,1}$ is recovered, the entry for $x_i$ is increased by $2$.
- If both $x_{i,0}, x_{i,1}$ are recovered, the entry for $x_i$ will have the value $3$.

We can write a function that updates and returns the occurencies based on a given message:

```python
def update_occurencies(current, msg):
    temp_current = current.copy()
    h = int(sha256(msg).hexdigest(), 16)
    bin_h = bin(h)[2:].zfill(N)
    for i, b in enumerate(bin_h):
        if b == '0':
            # if it's not already found
            if temp_current[i] not in [1, 3]:
                temp_current[i] += 1
        else:
            # if it's not already found
            if temp_current[i] not in [2, 3]:
                temp_current[i] += 2
    return temp_current
```

Therefore, let us pick a random message and update the occurencies based on it.

```python
import os

msg = os.urandom(16)
FOUND = update_occurencies([0 for _ in range(N)], msg)
TARGET = N*3
selected_msgs = [msg]
```

We know we have recovered the entire private key when the occurencies list contains only the value $3$. In other words, when the sum of the occurencies list is $3 \cdot N = 768$.

Having obtained 50% of the secret key, we need to focus on the rest 50% now.

The idea is to keep generating random messages up to some threshold and keep the message whose hash produces the biggest sum for the occurencies list. The threshold can be pretty much any value but we choose $2^{16}$ which is neither really big nor really small.

```python
def compute_msg_score(found, msg):
    new_found = update_occurencies(found, msg)
    return sum(new_found)

while True:
    mx = -1
    mx_msg = None
    for _ in range(2**16):
        msg = os.urandom(16)
        score = compute_msg_score(FOUND, msg)
        if score > mx:
            mx = score
            mx_msg = msg
    FOUND = update_occurencies(FOUND, mx_msg)
    selected_msgs.append(mx_msg)
    sm = sum(FOUND)
    print(f"Current {sm = }")
    if sm == TARGET:
        break

if len(selected_msgs) > LIMIT:
    print("Need less messages...")
    exit(-1)
```

Then, assuming the infinite loop terminates, we can send all of the 5 messages to the server, get their signature and obtain the entire secret key.

```python
for sel_msg in selected_msgs:
    h = int(sha256(sel_msg).hexdigest(), 16)
    bin_h = bin(h)[2:].zfill(N)
    sig = get_signature(sel_msg.hex())
    for i, b in enumerate(bin_h):
        SK[i][int(b)] = sig[i]
```

Finally, having recovered the private key, we sign the target message and send the signature along with the target message to the server and get the flag.

```python
TARGET_MSG = "d9_netadmin"

def sign(m: str, sk):
    h = int(sha256(m.encode()).hexdigest(), 16)
    hash_bin = list(map(int, bin(h)[2:].zfill(N)))
    sig = [sk[i][b] for i, b in enumerate(hash_bin)]
    return sig

def verify_signature(msg: str, sig: list):
    io.sendlineafter(b'> ', b'2')
    io.sendlineafter(b": ", msg.encode())
    io.sendlineafter(b": ", ",".join(s.to_bytes(length=N//8, byteorder="big").hex() for s in sig).encode())
    return io.recvline()

target_sig = sign(TARGET_MSG, SK)
print(verify_signature(TARGET_MSG, target_sig).strip())
```



## Getting the flag

A final summary of all that was said above:

1. Identify the Lamport one-time signature scheme
2. Notice that the same pair of keys is used to sign and verify several messages
3. Notice that there is an upper bound on how many messages we can sign
4. Apply a chosen-plaintext attack by choosing 5 chosen messages to sign such that they enable us to obtain the entire private key
5. Knowing the signing key, we can sign the target message and send the signature along with the target message to the server and get the flag
